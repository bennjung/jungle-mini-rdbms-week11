# SQL 처리기

## 기능

1. **명령어 토큰 파싱**: SQL 문장을 토큰으로 구분하고 명령의 구조를 분석한다.
2. **명령 분기 처리 및 실행**: 파싱 결과에 따라 `SELECT` 또는 `INSERT`를 실행한다.
   - `SELECT`: 테이블 파일에서 데이터를 읽어 출력한다.
   - `INSERT`: 테이블 파일에 데이터를 추가한다.

## 요구사항

출처: [Phase 1. SQL 처리기](../../resc/phase1.md)

- 텍스트 파일에 작성된 SQL 문을 CLI 명령을 통해 전달받는다.
- 최소 지원 명령은 `INSERT`, `SELECT`이다.
- 각 테이블은 파일로 관리한다.
- 스키마와 테이블은 이미 존재한다고 가정하며, `CREATE TABLE`은 구현하지 않는다.
- 원문에서는 저장 형식을 자유롭게 설계할 수 있도록 한다.

## 토큰 파싱 정책

```sql
INSERT INTO students VALUES (1, '김 철수, 학생');
```

**① 왼쪽부터 읽으며 토큰으로 나눈다.**

| 읽은 부분 | 처리 |
|---|---|
| `INSERT INTO students VALUES` | 문자열 밖의 공백을 기준으로 각각 구분 |
| `(`, `1`, `,` | 괄호·쉼표는 별도 기호 토큰, `1`은 숫자 토큰 |
| `'` | 문자열 시작 |
| `김 철수, 학생` | 문자열 안이므로 공백·쉼표도 내용으로 유지 |
| `'` | 문자열 종료. 전체를 하나의 문자열 토큰으로 묶음 |
| `)`, `;` | 각각 별도 기호 토큰 |

```text
[INSERT] [INTO] [students] [VALUES] [(] [1] [,] ['김 철수, 학생'] [)] [;]
```

**② 토큰 순서를 해석해 명령의 구조를 파악한다.**

```text
명령: INSERT
테이블: students
값: [1, '김 철수, 학생']
```

위 표기는 설명용이며, 내부 자료구조를 확정한 것은 아니다.

**문자열 안에 작은따옴표가 있다면:** `'철수''s 책'`의 `''`는 문자열 종료가 아니라 작은따옴표 한 글자다. 전체를 하나의 토큰으로 읽고, 값은 `철수's 책`으로 해석한다. 문자열 안의 괄호·세미콜론도 내용으로 취급한다.

※ SQL 토큰화와 CSV 읽기·쓰기 규칙은 별개다. 키워드 대소문자, 추가 리터럴, 주석, 오류 처리 정책은 미확정이다.

## 결정 사항: 데이터 저장 형식

- 테이블의 데이터 저장 형식은 **CSV**로 한다.
- `INSERT`는 데이터를 CSV 형식으로 기록하고, `SELECT`는 CSV 데이터를 읽어 출력한다.
- 일반적인 CSV 자체는 컬럼별 자료형을 정의하지 않는다. 컬럼의 자료형을 알려 주는 스키마 정보와 실제 데이터는 구분해야 한다.

## INSERT 실행 과정

```sql
INSERT INTO students VALUES (3, '민수');
```

`id`는 정수, `name`은 문자열인 테이블을 예로 들면:

```text
① 파싱 결과: 숫자 3, 문자열 "민수"
   ↓
② 스키마와 대조: id에 정수 3, name에 문자열 "민수"가 맞는지 확인
   ↓
③ CSV 형식으로 변환: 3,민수
   ↓
④ 테이블 파일에 레코드 추가
```

**자료형은 값의 종류이고, CSV는 값을 파일에 적는 규칙이다.** 이름이 `김,민수`라면 값 안의 쉼표를 구분자와 구별하도록 `3,"김,민수"`로 기록한다.

위 자료형은 설명용 예시이며, 실제 지원 자료형과 불일치 시 처리 정책은 미확정이다.

## 논의 사항: 컬럼의 자료형 저장 방식

요구사항은 스키마가 이미 존재한다고 가정하지만, 스키마 정보의 저장 위치와 표현 형식은 명시하지 않는다. 다음은 검토할 선택지이며, 아직 확정하지 않는다.

| 선택지 | 설명 |
|---|---|
| 별도 메타데이터 파일 | 컬럼 이름과 자료형 등을 파일에 저장한다. e.g. .json, .meta |
| 프로그램 코드 | 컬럼 이름과 자료형 등을 프로그램 코드 내부에 정의한다. |

별도 JSON 파일로 저장하는 방식과 코드 내부에 정의하는 방식은 구분한다.
- CSV를 읽을 때는 스키마 정보에 따라 텍스트 값을 해당 자료형으로 해석해야 한다.
- 메타데이터의 경로, 구체적인 구조, 지원 자료형은 미확정이다.
