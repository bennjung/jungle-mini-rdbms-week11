- ### 1. 우리가 해결하려는 문제와 목표
- **배경 상황:**
	- 결제나 포인트 서비스에서는 사고 추적과 정산을 위해 한 번 기록된 내역을 절대 수정하거나 삭제하지 않고 **계속 누적해서 쌓아 두기만 합니다.**
	- 이 내역을 단순 JSON이나 CSV 파일로 직접 다루면, "특정 회원의 내역만 뽑아달라"거나 "1,000원 이상 내역만 보여달라"는 요청이 생길 때마다 매번 파일을 통째로 열고 파싱하며 `for` 반복문을 새로 짜야 합니다.
- **Phase 1 목표:**
	- 애플리케이션이 파일 구조를 직접 건드리지 않고, **`INSERT`와 `SELECT` SQL 문장만 입력하면 거래 내역을 파일 끝에 안전하게 쌓고 조건에 맞게 꺼내주는 처리기**를 만듭니다.
- => 그러니 app은 sql을 통해 자료 구조를 신경쓰지 말고 데이터만 질의
-
-
  | **구분** | **요구사항** | **구체적 동작 기준** |
  |---|---|---|
  | **1. 테이블 정의** (고정 1개) | `users` (또는 `items`) | `id` (정수, 자동 증가), `name` (문자열), `age` (정수) 등 3~4개 컬럼으로 단순 고정 |
  | **2. 데이터 추가**  (`INSERT`) | `INSERT INTO users (name, age) VALUES ('김철수', 25);` | 입력받은 값을 검증한 뒤 `id`를 자동으로 붙여 파일에 저장 |
  | **3. 데이터 조회**(`SELECT`) | `SELECT * FROM users;``SELECT name, age FROM users WHERE id = 1;` | 전체 조회, 특정 컬럼 지정 조회, `WHERE` 단일 조건 필터링 |
  | **4. 영속성**(Persistence) | 프로그램 종료 후 재실행 | 기존 파일에 저장된 데이터가 유지되고, 다음 `INSERT` 시 `id`가 이어서 증가 |
  | **5. 예외 처리**(Validation) | 잘못된 SQL 문법 및 타입 입력 | 문법이 틀리거나 `age`에 문자를 넣으면 프로그램이 죽지 않고 에러 메시지 출력 |
	- 사용자 입력 txt로 명령 처리하므로 입력 잘못된 경우를 꼼꼼히 예외 처리 해줘야
	- 파일에 작성 도중에 종료됐을 때는 어떻게 해줘야 할지
	- 데이터 저장 로직을 추상화해서 처음에는 jsonl로 사용( escape  문자에 강해서), 이후에는 binary 등으로 바꿔도 재작성 비용 적도록 해야함
	- **데이터 조회 (`SELECT`):** `*` 및 지정 컬럼 순서대로 표 형태 출력, `WHERE` 조건절 비교 연산자(`=`, `!=`, `>`, `<`, `>=`, `<=` 및 `AND`) 지원
  - 
  - 타입 불일치 비교(age = 'abc' )  
  - 
  - Phase 3(동시성) 전이라도 팀원이 테스트하다가 터미널 창 2개를 띄워 동시에 INSERT를 날리면 두 프로세스가 같은 next_id(예: 둘 다 id=5)를 발급해 ID가 중복될 수 있습니다. Phase 1에서는 단일 프로세스 전제임을 명시하되, 동일 id 중복 방지 관점에서 인지하고 있어야 합니다.
